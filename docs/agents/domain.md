# Domain docs

This is a single-context repository.

## Required context

Before exploring or changing behavior:

1. Read the root `CONTEXT.md` glossary.
2. Read every ADR under `docs/adr/` that touches the area being changed.
3. Use glossary terms in specs, issues, tests, code review, and implementation notes.
4. Surface any ADR conflict explicitly instead of silently overriding it.

If a needed concept is absent from the glossary, note the gap for domain modeling instead of inventing a competing synonym.
