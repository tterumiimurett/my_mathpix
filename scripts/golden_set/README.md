# Fixed Golden Set evaluation

The 80 original, non-sensitive printed development Snippets are 30 Pure Formula, 20 simple-table, 20 mixed, and 10 separately reported boundary cases. They are not a claim to handwriting or representative private research screenshots. `build_corpus.py` authors the fixed truth and independent fixture HTML; never derive Golden Results from Datalab output. Once PNGs are frozen, do not regenerate without a new corpus version and input hashes.

The gated native runner uses the production RecognitionService and the App's existing private LocalTokenStore. It never migrates credentials, writes production Recent History, or uses the general pasteboard. No token, raw service exception, header, or unrelated screen content is printed. Run the same default bundle identifier so its own saved credential is available.

1. Build using `scripts/build_app.sh`.
2. Run `dist/MyMathpix.app/Contents/MacOS/MyMathpix --golden-set-render`. This writes a frozen Corpus under that App's sandbox `Library/Application Support/MyMathpix/GoldenSet/Corpus`. It waits for local fonts, verifies all formula elements rendered, rejects blank snapshots, and records PNG hashes.
3. Review all source/expected content and rendered fixture PNGs. Copy the explicit Corpus PNGs and manifest into `Sources/MyMathpix/Resources/GoldenSet/`, then rebuild and verify the signature. Do not export the whole sandbox container.
4. Run `dist/MyMathpix.app/Contents/MacOS/MyMathpix --golden-set-run=baseline-v1 --golden-set-limit=2`. The first two attempts are the first case in fast and balanced. Examine actual latency and available cost, then resume the same command with limit 160. Results are persisted per case/mode before consumption checks. Completed failures are retained rather than silently spent again. A changed executable, corpus or configuration requires a new run ID.
5. Inspect each returned Canonical Markdown, actual preview PNG, complete private pasteboard values and isolated AppModel edit/copy evidence. Record independent semantic/layout/consumption reviews, binding each to its input/content/output/corpus/configuration/artifact hashes. Unknown cannot pass. Corrected previews are separate artifacts. Batch clipboard serialization does not establish destination paste acceptance; accepted Markdown/Lark behavior and deferred Notion inline defect retain their existing evidence limits.
6. Generate reports with `python3 scripts/golden_set/report.py PATH_TO_RUN/manifest.json PATH_TO_RUN --reviews reviews.json --output report.json`. Without reviews, the quality gate stays pending. Fast and balanced are reported separately; no per-case best-of selection. Passing means at least 67/70 ordinary, with at least 27/30 formulas,18/20 tables,18/20 mixed. Boundary cases never alter the ordinary denominator.

Costs are stored in the API's cents unit with complete available cost breakdown, not assumed dollar values. Wall latency and API runtime are distinct. A full baseline makes 160 real Recognition Attempts; automatic technical retries are counted. Generated HTML has no remote renderer; bundled font resources are needed when reopening it. PNG previews are portable.

`python3 scripts/golden_set/test_report.py` checks the public report contract, fixed denominator, fail-closed hash binding, semantic equivalence and category floors. The repository's ordinary test scripts continue to cover production normalization, API transport, clipboard and persistence behavior. The Golden Set quality gate is additional evidence, not a replacement for Ticket06's signed-App capture journey.

Evaluator revision2 adds a public `--golden-set-preview-self-test` tall-document footer test, synchronized complete-window snapshots, and raw service Markdown/HTML retention with a raw-output hash. Baseline-v1 is preserved as a failed original assessment; baseline-v2 must be a separate full160-attempt run after production fixes. Do not reconstruct missing raw HTML from canonical output or Golden truth.
